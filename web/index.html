Kontrola před vydáním

Jeden testovací běh prověří API, data v SQL a nákup v prohlížeči. Každá chyba má postup k opakování a konkrétní výsledek.

Fiktivní ukázka. Obchod i závady jsou vytvořené pro toto portfolio. Testy běží nad izolovanou databází, ne nad skutečnými zákazníky.
Jak ReleaseGuard testuje API, SQL, Playwright a důkazy

Technologie: Node.js HTTP server, SQLite a Playwright. V prohlížeči běží jednoduché HTML/CSS/JavaScript rozhraní. Žádné externí API ani API klíč.

Postup: Každá ze sedmi kontrol dostane vlastní databázi. Testy porovnávají HTTP odpovědi, SQL stav i viditelnou cenu a nákupní tok. Přepínatelné závady mění skutečné chování fiktivního obchodu.

Důkazy: Report odděluje chybu produktu od chyby prostředí. Při selhání webového testu ukládá snímek a Playwright trace. JSON a JUnit XML lze použít v další kontrole.

Co testujeme

  • Schéma a stavové kódy API
  • Opakované požadavky a zásoby
  • Přesné SQL záznamy
  • Cenu a nákup na webu

Ruční obchod běží na vlastní fiktivní sadě v paměťové SQL databázi. Objednávky lze během běhu načíst podle ID přes API, ale po restartu serveru zmizí. Není zde seznam ani správa firemních objednávek. Každý automatický test má samostatnou izolovanou databázi; trvale se ukládá historie testovacích běhů.

METODIKA

Jak vzniká výsledek

ReleaseGuard hlásí jen pozorovaný rozdíl mezi očekáváním a skutečností. Vnější závislosti, například chybějící prohlížeč, označuje samostatně jako chybu prostředí.

01

Izolovaný vstup

Každá kontrola dostane novou SQLite databázi se stejnými fiktivními produkty.

02

API, SQL a prohlížeč

Kontroly volají skutečné HTTP endpointy, čtou SQL stav a používají Playwright pro webový nákup.

03

Reprodukovatelný nález

Protokol ukládá očekávání, zjištěný stav a kroky. Selhání v prohlížeči přidá screenshot a trace.

Přepínatelné závady jsou výuková simulace. Úspěšný běh potvrzuje těchto sedm kontrol, nikoli bezchybnost libovolného e-shopu.
